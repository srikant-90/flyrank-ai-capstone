1. Workflows vs. Agents: The Foundational Distinction

In modern AI architecture, the word "agent" is frequently overused to describe simple automated prompt sequences. However, Anthropic’s engineering research establishes a sharp, fundamental distinction between workflows and agents based on where control flow decision-making resides.

A Workflow is a system where the execution path, sequence of operations, and logic transitions are hardcoded by human developers. LLMs are used within workflows as structured processors at specific steps (such as extracting facts or formatting markdown), but the LLM does not decide what step happens next. The control flow is deterministic, static, and predictable.

An Agent, by contrast, is an autonomous system where an LLM dynamically directs its own execution loop. Given a high-level goal, the LLM continuously evaluates its progress, selects which tools to invoke, interprets tool feedback, and decides whether to stop or try another path. The control flow is non-deterministic, dynamic, and driven by the model’s internal reasoning loop.

Classification of the FL-04 Pipeline

Based on this strict definition, my FL-04 technical writing pipeline is explicitly a Workflow, not an agent. It follows a rigid 4-step linear chain: Gather & Extract → Structured Drafting → Adversarial Critique → Revision & Formatting. The handoffs between steps are pre-scripted. Step 1 always feeds Step 2, Step 2 always feeds Step 3, and Step 3 always feeds Step 4. At no point does the LLM decide to skip a step, loop back independently, or choose to call external tools on its own initiative.

2. Model Context Protocol (MCP) and Its Three Primitives

The Model Context Protocol (MCP) is an open standard designed to serve as the universal "USB-C port for AI applications." Before MCP, connecting an AI model to an external database, local file system, or enterprise API required custom integration code for every provider and tool pair. MCP replaces this fragmented ecosystem with a unified client-server protocol.

MCP architecture revolves around three fundamental primitives:

  • 1. Tools (Action Layer): Executable functions that the server exposes to the AI client. Tools allow models to perform side-effects or retrieve dynamic data (e.g., executing a terminal command, running a SQL query, or writing to a file). The client sends tool call arguments, and the server returns the execution result.
  • 2. Resources (Context Layer): Static or dynamic data sources attached to the model’s context. Unlike tools (which represent actions), resources represent readable context such as local file contents, application logs, or database schemas exposed safely to the LLM.
  • 3. Prompts (Template Layer): Pre-configured prompt templates hosted on the server that guide how models interact with specific resources or tools, providing consistent workflow shortcuts for users and clients.

3. Concrete Agent Upgrade: Transforming FL-04 into an Agent

To upgrade the deterministic FL-04 pipeline into a true Autonomous Research & Editing Agent, I would replace the fixed 4-step chain with a dynamic ReAct (Reasoning + Action) Evaluation Loop powered by MCP tools.

Instead of hardcoding a 4-step sequence, the upgraded agent would operate as follows:

  1. The user inputs a goal: "Generate a verified, production-ready technical migration guide for Next.js 16."
  2. The agent evaluates the request and autonomously invokes an MCP File Search tool (grep_search / view_file) to inspect the user's local repository dependencies and configuration files.
  3. If the agent detects missing information or version conflicts, it dynamically chooses to call an MCP Web Search tool (search_web) to pull live official documentation.
  4. The agent drafts the code and autonomously runs an MCP Terminal Execution tool (run_command) to execute npm run build in an isolated environment.
  5. If the terminal tool returns a build error (e.g. TypeScript type error), the agent reads the log error directly, reflects on the failure, edits the code via a file tool, and re-runs verification until the build passes cleanly.

This transforms a static 4-prompt assembly line into an autonomous, self-correcting agent loop capable of verifying its own work against real runtime environments.
