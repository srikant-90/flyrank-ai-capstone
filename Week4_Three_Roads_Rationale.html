Track: General AI Fluency

Assignment: Week 4 — "Three Roads"

Student Name: Srikant Behera

Selected Stack: Next.js (App Router) + Vercel + Tailwind CSS

1. My Four Constraints

  • Cost Constraint: $0 (Strictly free hosting, free tools, free API tiers).
  • Skill Level: Intermediate developer (MCA student; comfortable with React, TypeScript, Node.js basics).
  • Portfolio Content Needs: Displaying interactive AI tools (like real-time streaming chat), technical writeups, prompt logs, and GitHub repository links.
  • Display Formats: Interactive embedded tools, responsive component cards, clean typography for reading long-form logs, and direct source links.
  • Dynamic Data Need: Not yet. A full database backend is unnecessary overhead. Only lightweight serverless API route handlers are required to keep AI API keys secure.

2. Evaluation of Three Stack Options

Road 1 (Simplest): Static HTML/CSS + GitHub Pages

  • How to build: Standard HTML5, CSS3, and vanilla JavaScript.
  • Hosting: GitHub Pages (Free).
  • Backend Needed? No backend.
  • Real Trade-off: Ultra-fast and zero maintenance, but lacks serverless API route support. Live AI features cannot be integrated without exposing secret API keys to browser client code.

Road 2 (Chosen - Front-Runner): Next.js (App Router) + Vercel

  • How to build: Next.js, React, Tailwind CSS, Vercel AI SDK.
  • Hosting: Vercel (Free tier).
  • Backend Needed? "Not yet" (No full database backend; uses Next.js Serverless Route Handlers for API requests).
  • Real Trade-off: Slightly more setup than plain static HTML, but provides full React component flexibility, serverless route security for API keys, and instant Git continuous deployment.

Road 3 (Most Powerful): Full-Stack React SPA + Express.js API + PostgreSQL

  • How to build: React SPA, Express.js backend server, PostgreSQL database with Prisma.
  • Hosting: Render (Free tier) + Supabase (Free PostgreSQL).
  • Backend Needed? Yes, dedicated server and database backend.
  • Real Trade-off: High maintenance overhead. Free-tier backend servers spin down during inactivity (causing 30s cold-start delays for visitors), wasting time on DB administration rather than AI experiences.

3. Pressure-Testing the Front-Runner

  • What breaks if I pick the simplest (Static HTML)? I lose the ability to embed live, interactive AI tools safely. My portfolio would be limited to static screenshots.
  • What do I maintain if I pick the most powerful (Full-Stack Express + DB)? I would have to maintain CORS configurations, database migrations, connection pools, and cold-start latency.
  • Can I finish in two weeks? Yes. Next.js App Router allows modular component development while Vercel handles automated deployments.
  • Does it show my work the way it needs to be shown? Yes. It supports both long-form reading and interactive live AI tools.

4. Final Rationale & Decision

Selected Stack: Next.js (App Router) + Vercel + Tailwind CSS

Why I chose Next.js on Vercel: It strikes the exact balance between simplicity and modern web capabilities. It gives me built-in Serverless API Routes (/api/chat) to run AI features safely without managing a dedicated backend server.

Why I rejected Static HTML: Static HTML limits the portfolio to passive reading. Demonstrating working AI streaming tools requires serverless execution.

Why I rejected Full-Stack Express + Database: Answering the backend question honestly: I do not need a database yet. Database setup would consume development time needed for core portfolio features.

Can I maintain this? Yes. Vercel automatically deploys updates directly from my GitHub repository's main branch with zero server management.
